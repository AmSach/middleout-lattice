# Middleout-Lattice Core Documentation

This document explains the architectural principles, core algorithms, Python/C++ APIs, and CLI usage of the **Middleout-Lattice** compression engine.

---

## 1. Core Architecture & Basic Principles

Middleout-Lattice is a **type-aware, multi-stage hybrid compression engine**. Unlike general-purpose compressors (like Gzip, Zstd, or Gzip) that treat all files as arbitrary byte streams, Middleout-Lattice dynamically routes different file types through custom pre-processing pipelines before final entropy coding.

```
                  ┌─► Text/JSON ─────► BPE / Word Tokenizer ──► solid block BWT/PPM ──┐
                  │                                                                   │
                  ├─► ML Weights ────► AVX2 Plane Transposition ──► Zstd (L22) ───────┼─► .lattice
Input Files ─────┼─► WAV Audio ─────► 16-bit Channel Split ────────► Zstd (L12) ──────┤   Archive
                  │                                                                   │
                  └─► Other Binaries ─► trained dictionary ─────────► Zstd ────────────┘
```

### A. AVX2 Byte-Plane Transposition (Tensors & Floats)
*   **The Problem:** Floating-point numbers (`float32`, `float16`) generated by training models have highly noisy mantissa bits but highly uniform sign/exponent bits. In a raw float array, these bytes alternate, creating a high-entropy stream that standard compressors cannot compress.
*   **The Innovation:** Middleout-Lattice transposes the layout of the float array. Instead of storing elements as `[f0, f1, f2, f3]`, it groups all the sign/exponent bytes (byte 3) together, then all upper mantissa bytes (byte 2), and so on:
    $$\text{Original Layout: } [b_3, b_2, b_1, b_0]_0, [b_3, b_2, b_1, b_0]_1, \dots$$
    $$\text{Transposed Layout: } [b_3^0, b_3^1, \dots], [b_2^0, b_2^1, \dots], [b_1^0, b_1^1, \dots], [b_0^0, b_0^1, \dots]$$
*   **The Result:** Grouping similar exponent bytes exposes long, repeating sequences. Zstd's entropy coder can compress the exponent and sign planes to almost zero, achieving **1.2x to 1.28x** lossless compression, outperforming competitors.
*   **AVX2 Optimization:** The transposition is fully SIMD-accelerated in C++ using AVX2 registers, processing bytes at over **10 GB/s**.

### B. Multi-Level Virtually Lossless Weight Masking
For scenarios where tiny loss of precision is acceptable (e.g., model storage, distribution, MLOps), Lattice provides 5 levels of masking:
*   **Level 0 (Lossless):** Exponents and mantissas are stored exactly (MSE = 0.0).
*   **Level 1 (Virtually Lossless - Ultra):** Zeroes the lowest 8 bits of the mantissa. MSE $\approx 10^{-13}$.
*   **Level 2 (Virtually Lossless - High):** Zeroes the lowest 16 bits of the mantissa. MSE $\approx 10^{-8}$. Beats FP16 storage footprint (2.0x) with better precision.
*   **Level 3 (Virtually Lossless - Medium):** Zeroes the lowest 23 bits of the mantissa (keeps 1 mantissa bit). MSE $\approx 1.8 \times 10^{-4}$. Beats 8-bit quantization size (4x) while preserving full dynamic range.
*   **Level 4 (Lossy - Max):** Zeroes the lowest 24 bits (keeps sign + 7 exponent bits). MSE $\approx 2.3 \times 10^{-4}$. Beats 8-bit size by 3x, matching 4-bit quantization size without outlier weight clipping.

### C. Text & Code BPE/Word Tokenization
*   Lattice uses a static dictionary of common programming keywords and indentation depths to tokenize text/code before compression.
*   For files under 500KB in `--best` mode, it uses a hybrid **Order-16 PPM (Prediction by Partial Matching)** context mixer combined with a C++ Range Coder to model character probabilities dynamically.

## 2. API Reference

### Python API (`lattice_archive.py`)

#### `LatticeArchiveEngine.compress`
```python
@staticmethod
def compress(src_path, output_archive_path, virtually_lossless=0, solid=True, progress_callback=None)
```
*   **`src_path`**: Path to a file or directory to compress.
*   **`output_archive_path`**: Destination `.lattice` archive file.
*   **`virtually_lossless`**: Compression level (`0` to `4` or custom bit count `1` to `24`).
*   **`solid`**: If `True`, packs multiple files into a single solid block to exploit cross-file redundancy.
*   **`progress_callback`**: Optional function called as `fn(index, total_files, current_path, bytes_processed)`.

#### `LatticeArchiveEngine.decompress`
```python
@staticmethod
def decompress(archive_path, dest_dir, progress_callback=None)
```
*   **`archive_path`**: Path to the `.lattice` archive to extract.
*   **`dest_dir`**: Target directory where files will be extracted.

## 3. CLI Command-Line Interface (`lattice_cli`)

### Compression

```bash
# Basic lossless compression
lattice_cli compress my_model/ model.lattice

# Solid-block compression for maximum ratio
lattice_cli compress my_model/ model.lattice --solid

# Level 2 virtually lossless compression (3x size reduction)
lattice_cli compress my_model/ model.lattice --vl 2

# Level 4 maximum compression (12x size reduction)
lattice_cli compress my_model/ model.lattice --vl 4
```

### Decompression

```bash
# Decompress to output folder
lattice_cli decompress model.lattice ./extracted_model/
```

## 4. Why This Beats Standard Quantization

Standard quantization (like INT8 or INT4) divides weights into blocks and divides each weight by a shared scale factor, clamping the result. This has a major weakness: **outliers**. If a block contains one huge weight, the scale factor expands, compressing the resolution of all other weights in that block down to zero.

Lattice's Level 3 and 4 masking keeps each weight's **exponent independently**. Because each weight has its own scale, **no outlier clipping occurs**. Every weight preserves its approximate magnitude, resulting in higher neural network accuracy at equivalent compressed sizes.
